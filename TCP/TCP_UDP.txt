# 🚀 TCP & UDP — Part 1: Why do we need them?

Before learning TCP and UDP, there is **one small concept** we need to understand.

You already know:

> **IP address identifies a device on a network.**

For example:

```text
192.168.1.10
```

Suppose this computer is running **three applications**:

```text
192.168.1.10
│
├── Web browser
├── SSH
└── Database
```

Now imagine another computer sends something to:

```text
192.168.1.10
```

### ❓Problem

The IP address tells us:

> "Send this data to computer `192.168.1.10`."

But the computer has **many applications** running.

So how does the computer know:

> "This data is for the web browser, not SSH or the database"?

That's where **PORT NUMBERS** come in.

---

# 🔑 Port Number

A **port** identifies a particular application/service on a device.

Think of it like this:

```text
IP address = House address
Port = Room number
```

For example:

```text
192.168.1.10:80
```

means:

```text
192.168.1.10 → Which computer?
80            → Which service?
```

So:

> **IP address identifies the device.**
> **Port identifies the service/application.**

---

## Example

Suppose your server has:

```text
192.168.1.10
```

and it's running:

```text
Web server      → Port 80
HTTPS server    → Port 443
SSH             → Port 22
```

Then:

```text
192.168.1.10:80
```

means:

> Send the traffic to the web service.

And:

```text
192.168.1.10:22
```

means:

> Send the traffic to SSH.

---

# 🧠 Now where do TCP and UDP come in?

We now have:

```text
IP address
     ↓
Which device?
     ↓
Port
     ↓
Which application?
```

But we still need to decide **HOW the data should be transported**.

That's the job of the **Transport Layer**.

And the two major transport protocols you'll learn are:

```text
             Transport Layer
                    │
             ┌──────┴──────┐
             ↓             ↓
            TCP           UDP
```

### TCP

TCP focuses on:

> **Reliable delivery**

It makes sure data is delivered properly, in the correct order, and handles retransmission when needed.

### UDP

UDP focuses on:

> **Speed and simplicity**

It sends data without establishing the same kind of connection/reliability mechanism that TCP uses.

---

# 🌐 Putting everything together

Imagine your browser wants to connect to a web server:

```text
Your computer
192.168.1.10
      │
      │
      ↓
Destination
192.168.1.20:443
      │
      ↓
     HTTPS
```

Here:

```text
192.168.1.20
      ↑
    IP address
    = device
```

```text
443
 ↑
Port
= service
```

And underneath the application communication, **TCP** can provide the reliable transport.

So conceptually:

```text
Application
    ↓
HTTPS
    ↓
TCP
    ↓
IP
    ↓
Network
```

This is going to become **very important in DevOps**, because later when you work with:

* Docker
* Kubernetes
* Linux servers
* Load balancers
* Firewalls
* Cloud networking
* Web servers
* Databases

you'll constantly see things like:

```text
IP:PORT
```

For example:

```text
80
443
22
3306
5432
8080
```

---

## 🎯 One thing I want you to remember

Don't memorize TCP/UDP yet.

First understand this chain:

> **IP → identifies the machine**
> **Port → identifies the service**
> **TCP/UDP → determines how data is transported**

That's our foundation.

### 📝 Your first exercise

Suppose we have:

```text
192.168.1.50:22
```

Tell me:

**1. What does `192.168.1.50` identify?**

**2. What does `22` identify?**

**3. If IP identifies the device and port identifies the service, then what is TCP/UDP responsible for?**

Answer these in your own words. Then we'll move to **TCP vs UDP**.
